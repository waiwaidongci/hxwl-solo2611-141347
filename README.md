# 海港集装箱空箱验收复检分流

`hxwl-solo2611-14` · 分类的模型选择

闸口按设备交接单登记干货空箱的凹陷、门缝、地板含水率和可见污迹。验箱室用已结案记录比较复检分流方案，为当班待验箱安排常规验收、复检工位或留置。班长复核后，堆场调度据单安排箱位，验箱员回填实判。

## 模拟客户与工作流

澄浦海港北区空箱堆场 · 18 名验箱与堆场调度人员，两班日均接收 420 只干货空箱（模拟）

- 闸口初检和验箱室实判分存在两张表，跨班对单常漏掉晚回填的结案。
- 验箱员拿不准时就安排二次倒箱，忙班复检队列挤占常规入场通道。
- 同类异常分散在历史交接单里，班长很难当场说明为什么要复查某个部位。

闸口验箱班长先核对留置单，再对复检单查阅相似交接单和实判部位。确认后派单给北区堆场调度与设备验箱班；调度安排复检工位，验箱员复核并回填实判。

## 业务模块

- 闸口验箱台账
- 复检方案试算
- 分流与留出核验
- 班次派单与收件

## 计算口径

同一初检日只进入一个时间段。验证仅使用训练截止前已实判入账的参考箱。先按验证段总成本选 k，同成本依次取漏检更少、k 更小的方案。随后用验证截止前已入账的训练与验证数据重拟合，留出段只评估一次，待验分流沿用冻结版本。

常规箱按训练参考集的标准差缩放四项闸口读数，恒定特征跳过，非恒定特征的缩放分母至少为 0.01，箱型不同计一个距离单位。使用欧氏距离和 1/距离加权；存在零距离时只用零距离票。排除与查询同箱号的历史单。异常票占比达到阈值送复检。

疑似结构险及不明残留各走现场留置规程，跳过打分。估算总成本为送复检或留置核验数 × 单箱复检成本 + 漏检数 × 单箱损失。样本历史由验箱室全量复核；只给高疑似箱补标签的历史会让成本评估失真。

实判接受完好、结构修理、门封修理、烘干处理、清洗处理与隔离处置。模型票比用于当班分流，常规通道仍须验箱员按堆场规程验收签字。

样例输入为 `澄浦北区空箱验收_20261124.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 11 月 24 日 07:40，闸口班长导入《澄浦北区空箱验收_20261124.csv》，核对 8 只待验箱的交接单与箱型。
2. 07:55，验箱室核定 11 月 13 日、17 日、22 日三个截止点，确认验证及留出段实判已经入账。
3. 08:05，调度填入候选 k 为 1、3、5、7，复检阈值 45%，估算复检 55 元/箱、漏检 380 元/箱并提交试算。
4. 08:12，班长先看验证成本选出的 k，再看留出段复检数、漏检数及全量复检对照成本。
5. 08:20，按闸口留置规定处理疑似结构险单 EIR-1124-05 和不明残留单 EIR-1124-06。
6. 08:24，打开 EIR-1124-02 的邻居证据，查阅历史门封异常交接单，给复检工位交代门封核对项。
7. 08:35，班长完成业务复核，向北区堆场调度组和设备验箱一班发出站内分流清单，实判随后由验箱室记账。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18323`，API `http://127.0.0.1:19323`，数据库宿主端口 `17823`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 MySQL 8.0 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
